# 统一缓存管理

## 管理入口与作用范围

`Meili.Core/Abstractions/IManagedCache.cs` 定义缓存身份、统计和清理契约；Application 的 `Meili.Caching.CacheManager` 是桌面、CLI 和 MCP 共用的维护入口。保持各缓存原有读写路径和 TTL，不引入后台统计轮询。

| 类别 | 桌面 | CLI/MCP | 作用范围与行为 |
| --- | --- | --- | --- |
| responses | 是 | 是 | 当前进程的供应商响应；按原 TTL、约 2,000 项容量管理 |
| bars | 是 | 是 | 数据目录共享 SQLite；支持股票筛选，同时清理该股票所有周期和复权方式 |
| quotes | 是 | 不实例化 | 当前进程 QuoteHub；失效复用时间，保留最后报价显示和所有订阅 |
| search | 是 | 不实例化 | 当前进程代码搜索；10 分钟 TTL、200 项容量，并合并相同在途查询 |
| rates | 是 | 不实例化 | 当前进程国债收益率；6 小时 TTL、15 分钟失败退避；保留用户固定利率 |

每个进程只报告自己注册的内存缓存，不能声称清理了另一个桌面/MCP 进程的内存。全量清理只包含当前注册项。不支持的类别/筛选组合在变更前拒绝。

## 使用

设置页：缓存卡片提供类别选择、刷新统计、清理过期和清理所选。全量清理经现有 AppDialog 确认；繁忙状态复用 AppLoading、按钮禁用和 reduced-motion 行为。帮助通过 AppHelp 提供。无自动清理计时器。

```sh
easysellput cache status --json
easysellput cache clear --category responses --mode expired --json
easysellput cache clear --category bars --symbol AAPL --json
easysellput cache clear --category all --json
```

MCP：`get_cache_status` 是只读工具；`clear_cache` 仅在显式 `--allow-writes` 时暴露，未授权调用仍由服务边界拒绝。参数为 `category`、可选 `mode`（`all` / `expired`）、可选 `symbol`（仅 `bars`）。CLI 的直接操作名同样可用。伴随 skill 提供维护指引，未增加文件删除、浏览器清理或 shell 工具。

统计包含 entries、expired、可用时的 hits/misses、存储和作用范围、策略。无法可靠测量的内存字节数用 null；bars 的 sharedFileBytes 是数据库及 WAL/SHM 的物理总量，包含历史数据，不能解释为可回收大小。命中/未命中计数是进程生命周期累计值，不因清理重置。

## 不可混淆的数据边界

- 清理仅删除 `bars` / `bar_meta` 的目标行；不删除数据库文件，不运行 VACUUM。
- `iv_samples` 和 `oi_daily` 是历史观测，不是可随时重新下载的临时响应；永不由此入口删除。
- 设置、自选、策略、提醒、画线、书签原样保留。
- OS WebView 缓存/Cookie、个人网页会话、页面实例、数据源认证与健康状态、更新下载明确列入 excluded；不假装已管理或清理这些资源。
- bars 没有固定 TTL，因此 `expired` 模式保留 K 线；明确全量清理后会失去对应的离线数据。
- quotes 的结果用 `invalidated` 表示失效条目，`removed` 为 0；最后显示值保留不等于仍然可以命中短期缓存。

## 并发、兼容与失败

响应缓存按清理代次隔离，在途调用仍可完成，但不能重新填入清理前的值；后续调用启动新代次请求。搜索复用同一实现。报价保留订阅；清理前请求不成为新的鲜活缓存，也不覆盖清理后的缓存。

SQLite schema 4 增加 `cache_generation`。清理和递增代次在同一事务提交；K 线网络请求开始前读取代次，保存完整数据或尾部合并时在事务内检查。独立桌面/CLI/MCP 实例因此共享清理边界。按股票清理也递增全局代次：同时进行的其他股票旧请求可能跳过一次缓存写入，但仍将结果返回调用者，后续请求正常重建。

旧版进程尚未实现代次检查，不能保证混合新旧程序时阻止旧版写回；升级时应退出旧实例。清理不取消数据读取、不清除行情订阅、不改刷新频率。多类别不是跨内存/SQLite 的原子事务；某项故障时可能已有前序项完成，UI 显示失败并建议重试。SQLite 自身的删除与代次更新保持原子性。

完整下载/尾部刷新、断网回退及原有历史保留规则继续沿用；本次未增加全局磁盘配额或旧股票自动淘汰。后续需实现新策略时通过这一入口扩展，不能另写目录删除逻辑。

## 分段存储占用条

设置页现在用可复用 `AppStorageBar` 替代内存条目摘要，右上显示数据目录文件总大小，下方以实际大小比例展示行情数据库、网页数据、用户数据、日志、其他缓存和其他文件。图例显示分类大小，悬停色块可读对应类别；零占用分类保留图例，不人为放大色块。空数据不会制造已使用比例。中英文、明暗主题和窄窗口共用相同组件，颜色及尺寸来自设计 tokens。

总量属于应用数据目录，不是整盘容量、可回收容量或进程内存；按文件逻辑大小计量，不声称是底层文件系统分配块。共享数据库/WAL/SHM 归同一类别，包含不可由缓存入口清除的 IV/OI 历史。更新包如果位于系统临时目录，不计入此目录统计。

`get_cache_status` 的 `storage` 字段供 CLI/MCP 读取同一数据。每次刷新/清理后按需后台扫描，不增加计时器；最多扫描 200,000 个目录项、深度 32，不跟随链接，不读取文件内容或输出 Cookie/文件名。无法完整遍历时 `complete=false`、`skipped>0`，界面显示不完整提示；统计期间文件变化仍可能影响快照。

本次新增分类求和、扫描上限、取消、外部链接跳过测试，以及真实布局的比例、窗口缩放和空数据测试。完整离线脚本通过（804 项 .NET、54 项 Python、47 项 CLI/MCP 能力）；最后的间距与空提示折叠调整另跑受影响的 6 项 UI 测试通过。Windows 应用和完整测试项目交叉构建通过；原生 WPF 执行仍交由 GitHub Actions。


## QQQ GEX 接入（本地迁移中）

桌面、CLI 和 MCP 均通过同一 CacheManager 注册 `qqq_gex_wire`。设置页可选择该类别；只读 `get_cache_status` 报告条目数、过期数和响应正文逻辑字节数（不是整个数据库的可回收空间）。`expires_at` 原样保留；256 MiB wire 正文预算按最早来源时间淘汰。容量淘汰后的采集结果明确为 `wireCoverage=capacity-limited`，不能声称所有查询都已预热。

`cache/qqq-gex.db` 同时包含不可恢复的观测与可重建响应，因此存储图单列 GEX 归档与派生数据，整个分段不可删除。清理只删除 `qqq_gex_wire` 并失效导入复用回执；不删除 provider 原始字节、标准化输入、完整/partial 日 profiles、bars、日摘要和历史导入进度，不删除文件或 VACUUM。CLI/MCP 与桌面都使用这条保全边界；`all` 同样保留观测。

`qqq_gex_cache_meta.generation` 在清理事务中递增。计算开始前读取代次，原子发布前再次核对；清理期间启动前的计算不会写回旧缓存。精确相同输入仅在回执、日 revision 和内容哈希通过时复用；清理或数据变更使其失效。没有新增后台清理计时器。

增加了 Data 的统计、容量/过期清理及原始观测保全测试；生产 CLI/MCP smoke 检查 GEX 注册与跨进程清理后历史保留；Node 采集发布测试用独立进程验证清理代次 fencing。原生平台验收仍须在 Windows/macOS 执行，不能用 Linux 编译替代。
