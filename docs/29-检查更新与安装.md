# 检查更新、阅读与安装

设置页顶部提供「软件更新」卡片。默认手动检查，不在后台下载或替换应用。

1. **检查更新**：从构建时绑定的 GitHub 仓库稳定 Releases 检查（Actions 使用 `GITHUB_REPOSITORY`；上游读取上游、fork 读取 fork），排除草稿和预发布。版本号显示当前 → 新版本；没有正式版本会明确提示，不冒充网络检查成功或已是最新。
2. **更新内容**：默认折叠，点击查看发行说明；以文本呈现，不执行 HTML、脚本或其中的指令。「版本历史」打开固定的官方页面。
3. **下载更新**：自动选择当前 Windows x64 / macOS Intel/Apple Silicon 架构包。先验证固定 ECDSA 公钥签名，再对流式下载核对签名清单中的文件名、字节数和 SHA-256。失败/取消清理临时文件，不覆盖已验证缓存。
4. **安装并重启**：用户确认后，复制旧版自带 CLI 到独立临时目录启动安装助手。先复验签名/哈希、解压、校验布局与 macOS bundle 签名、检查安装目录权限和活跃进程；成功发出 ready 后 GUI 才正常退出。随后同卷重命名替换、保留旧应用备份并重启。

Windows 便携 `data` 随事务移动，外置用户目录不移动。应用、CLI/MCP、skill 同包更新，原路径保持以兼容客户端配置。当前数据目录内还有 MCP 会话或同一安装目录中的其他实例时拒绝替换，不强杀用户的 AI 工具。替换失败按逆序回退；回退/启动失败的备份及暂存保留供人工恢复，不清空数据。安装状态另存于用户 profile 的 EasySellPut-Updater/state，避免安装目录搬移时丢失结果。

开发输出、macOS App Translocation、符号链接安装目录、无写权限的安装位置不自动更新；通过官方版本页手动安装。自定义数据目录位于安装目录内部且不是标准 `data` 时，先移到外部再安装。无提权、无系统命令拼接、无 Gatekeeper/执行策略绕过。

## 发布配置

GitHub 的 `release` Environment 仅允许 `main`。服务器使用 `UPDATE_SIGNING_KEY` 对更新清单和独立应用签名。仓库已有固定公钥时，使用与之匹配的私钥备份，从有仓库管理权限的维护者电脑执行：

```sh
python3 build/setup-update-signing.py --key /path/to/update-signing.pem --upload
```

私钥保存在仓库外。已有发布或已分发使用该公钥的客户端时，继续使用原密钥。初始化新密钥需要单独确认现有信任和安装情况。

待当前 `main` 的完整 CI 通过后，`Release · Auto publish` 可按仓库开关自动发布，也可手动指定该次 main push 的 CI run ID 准备草稿。手动准备后运行 `Release · Publish`。Windows 包无需 Authenticode 证书，macOS 包保留本地 ad-hoc 完整性签名，无需 Developer ID 或公证。主程序仍验证正式发行的项目清单签名和附件散列。见 [发布流程](44-GitHubActions主分支发布流程.md)。

## CLI 和 MCP

```sh
easysellput update check --json
easysellput update download --json
```

支持 `--data-dir PATH` 以使用该目录的网络配置。下载不会安装；桌面交互确认才触发退出与安装。`update apply --plan PATH` 是桌面助手的内部交接命令，不是远程接口。

更新是本地软件维护，不新增市场/策略业务操作。MCP 不暴露下载执行代码、自我替换、关闭进程或任意 URL 工具；原有业务目录和读写授权不变。安装前明确要求断开活跃 MCP，安装后按需重新连接。

## 验证与限制

- 应用测试：签名篡改、非信任密钥、重定向域、哈希/大小、压缩路径/链接、权限及便携数据替换/回退。
- 桌面测试：无自动检查、手动检查/阅读、取消、确认与否、活跃 MCP 拒绝、验证失败时不退出，以及中英文深浅主题的实际截图。
- Native CI：对真实解压后的三个桌面目标的客户端调用生产提取与替换逻辑，保留样本数据/备份，再启动被替换的真实 GUI，验证签名与常规自检。测试代码不进入发行包。
- 当前未发布正式 Release，也未在用户机器上执行实际在线升级。签名信任与下载使用测试密钥/fixture 单独验证；原生执行结果以 Actions 为准。重启成功调用不代表新进程的所有未来业务状态都已被健康检查；备份持续保留。

## 自动绑定更新源

仓库来源在编译时写入 Application assembly metadata，不再硬编码 fork，也不在运行时读取环境变量、git remote 或偏好设置。本地构建默认不启用更新检查，设置页显示“开发构建未配置更新源”，启动不会请求发布服务器。

使用 `easysellput update source --json` 可离线查看内置仓库、公钥 SHA-256 和是否启用。CI 和签名后原生包检查都会对照当前仓库及源码公钥验证 GUI/CLI；错误仓库、错误公钥、禁用的发布包会阻止发行。签名更新索引增加 `repository`，客户端和安装助手使用同一个仓库校验规则，不跨仓库回退。

合入 `ytqciscocarl/EasySellPut` 后，由该仓库 Actions 构建的客户端自动检查 `https://api.github.com/repos/ytqciscocarl/EasySellPut/releases/latest`。在 fork 中构建则继续检查 fork。正式发布需要与构建内置公钥匹配的项目私钥。旧安装包保留旧地址，迁移时需安装新客户端；不自动改写已有客户端信任。
