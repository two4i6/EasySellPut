# 检查更新、阅读与安装

设置页顶部提供「软件更新」卡片。默认手动检查，不在后台下载或替换应用。

1. **检查更新**：从固定的 GitHub `two4i6/EasySellPut` 稳定 Releases 检查，排除草稿和预发布。版本号显示当前 → 新版本；没有正式版本会明确提示，不冒充网络检查成功或已是最新。
2. **更新内容**：默认折叠，点击查看发行说明；以文本呈现，不执行 HTML、脚本或其中的指令。「版本历史」打开固定的官方页面。
3. **下载更新**：自动选择当前 Windows/macOS x64/ARM64 架构包。先验证固定 ECDSA 公钥签名，再对流式下载核对签名清单中的文件名、字节数和 SHA-256。失败/取消清理临时文件，不覆盖已验证缓存。
4. **安装并重启**：用户确认后，复制旧版自带 CLI 到独立临时目录启动安装助手。先复验签名/哈希、解压、校验布局与 macOS bundle 签名、检查安装目录权限和活跃进程；成功发出 ready 后 GUI 才正常退出。随后同卷重命名替换、保留旧应用备份并重启。

Windows 便携 `data` 随事务移动，外置用户目录不移动。应用、CLI/MCP、skill 同包更新，原路径保持以兼容客户端配置。当前数据目录内还有 MCP 会话或同一安装目录中的其他实例时拒绝替换，不强杀用户的 AI 工具。替换失败按逆序回退；回退/启动失败的备份及暂存保留供人工恢复，不清空数据。安装状态另存于用户 profile 的 EasySellPut-Updater/state，避免安装目录搬移时丢失结果。

开发输出、macOS App Translocation、符号链接安装目录、无写权限的安装位置不自动更新；通过官方版本页手动安装。自定义数据目录位于安装目录内部且不是标准 `data` 时，先移到外部再安装。无提权、无系统命令拼接、无 Gatekeeper/执行策略绕过。

## 首次发布前的必要配置

**当前公钥是开发引导占位。首次正式发布前必须初始化自己的发布密钥、提交新公钥并重新构建客户端。** 本任务的 GitHub 集成凭证调用 Actions Secrets API 返回 403，不能替维护者完成 secret 配置。

在有仓库 Secrets 写权限、已登录 `gh` 的维护者电脑上，准备 Python、OpenSSL、GitHub CLI，然后在仓库执行一次：

```sh
python3 build/setup-update-signing.py --key "$HOME/.config/EasySellPut/update-signing.pem" --initialize --upload
```

Windows PowerShell 对应命令：

```powershell
python build/setup-update-signing.py --key "$env:LOCALAPPDATA\EasySellPut-signing\update-signing.pem" --initialize --upload
```

脚本在仓库外保留私钥备份，只把公钥写入源码，并用本机 gh 登录将私钥通过标准输入配置到 Actions 的 `UPDATE_SIGNING_KEY`。不打印私钥、不自动提交或发布。公钥变更需提交并重新通过 CI，**之后**构建的官方客户端才能验证相应更新。不要把私钥提交到 Git；已有正式版本时脚本拒绝重新初始化，继续使用原密钥。丢失旧密钥或轮换需要单独的客户端信任迁移。

## 维护者准备发行

将工作分支合入默认分支，使手动发布 workflow 可见，然后：

1. 更新 Directory.Build.props 的稳定三段版本号，编写面向用户的更新说明。
2. 等 CI 的 `CLI and MCP required` 全部通过，保留该次 push run id。
3. 手动运行 **Prepare signed update draft**，输入该 CI run id 和说明。
4. workflow 只接受本仓库 main/work 的成功 CI push run，下载四份原生 Desktop 包，复核校验和/大小，生成 `EasySellPut-update.json` 并签名。
5. workflow 创建包含所有 zip、sha256、清单和签名的 **Release 草稿**，不自动发布，不覆盖已有版本。审核后由维护者手动 Publish。

客户端只接受正式稳定 Release，CI artifacts 或未签名 zip 不会自动安装。清单签名验证的是本项目发行授权；它不等于 Windows Authenticode 或 macOS Developer ID/公证。CI 的 ad-hoc macOS 签名仍按现有方式标明。

## CLI 和 MCP

```sh
easysellput update check --json
easysellput update download --json
```

支持 `--data-dir PATH` 以使用该目录的网络配置。下载不会安装；桌面交互确认才触发退出与安装。`update apply --plan PATH` 是桌面助手的内部交接命令，不是远程接口。

更新是本地软件维护，不新增市场/策略业务操作。MCP 不暴露下载执行代码、自我替换、关闭进程或任意 URL 工具；原有业务目录和读写授权不变。安装前明确要求断开活跃 MCP，安装后按需重新连接。

## 验证与限制

- 应用测试：签名篡改、非信任密钥、重定向域、哈希/大小、压缩路径/链接、权限及便携数据替换/回退。
- 桌面测试：无自动检查、手动检查/阅读、取消、确认与否、活跃 MCP 拒绝、验证失败时不退出，以及中英文深浅主题的实际截图。
- Native CI：对真实解压后的四架构客户端调用生产提取与替换逻辑，保留样本数据/备份，再启动被替换的真实 GUI，验证签名与常规自检。测试代码不进入发行包。
- 当前未发布正式 Release，也未在用户机器上执行实际在线升级。签名信任与下载使用测试密钥/fixture 单独验证；原生执行结果以 Actions 为准。重启成功调用不代表新进程的所有未来业务状态都已被健康检查；备份持续保留。
