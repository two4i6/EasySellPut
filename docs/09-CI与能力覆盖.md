# GitHub Actions：CLI 与 MCP 覆盖门禁

## 工作流

`.github/workflows/ci.yml` 在 push、pull_request、workflow_dispatch 时运行，不按文件路径跳过检查，不依赖用户密钥，不调用实时行情接口。仓库权限为 contents: read，checkout 不保留凭证。

- `CLI and MCP (ubuntu-24.04 / windows-latest / macos-15-intel)`：固定 global.json SDK，运行 Core/Data/Analytics/Shared/Automation 离线业务测试、覆盖门禁反例测试、逐操作双入口检查、生产 CLI/MCP 进程检查，并发布与当前 runner 架构匹配的自包含程序，在对应系统实际执行。
- `Desktop headless regression`：Linux 安装 Noto/DejaVu 字体，执行现有 Avalonia 无窗口 UI 回归，避免自动化入口改动破坏桌面。
- `CLI and MCP required`：固定名称的汇总检查；上述任一任务失败、取消或跳过均不通过。矩阵任务 fail-fast=false，便于保留所有平台的证据。

TRX、逐操作覆盖 JSON 和 UI 截图通过 artifact 保留 14 天。开发版、发行版和跨平台实际运行结果以 GitHub 上的运行结果为准；在 Linux 本地执行不代表已跑过 Windows/macOS 托管 runner。

## 新增操作的要求

1. 在共享服务实现业务，更新 `OperationCatalog` 的输入 Schema、读写属性及描述。
2. 在 `tests/automation/capability_cases.json` 添加该操作的场景：arguments、expect、compare；需要衔接创建出的 id 时，用 capture 和 `${name}` 引用。
3. expect 必须包含业务 data 的实际期望值，例如价格、计算结果、保存后的规则或删除的 id，不能只断言 success。compare 指定两个入口必须一致的字段；不要比较生成时间、随机 id 或不同临时目录。
4. 若新功能需要行情，扩展 `tests/Meili.Automation.Tests/FakeMarket.cs` 或测试专用主机。生产入口不提供 fake 模式；测试主机通过代码注入数据，实际运行同一 CLI 解析器和官方 MCP SDK。
5. 增加边界条件与必要的算法测试，并在 PR 模板中说明桌面、CLI、MCP 各入口的覆盖情况。

检查器从已编译程序的 `--help --json` 获取完整目录，不用正则扫描源码或固定工具数量。它要求用例集合与目录完全相等，再核对 MCP 工具集合、Schema、只读属性，执行每项 CLI/MCP 场景并核对结果；默认只读进程还逐项拒绝所有修改工具的直接调用。

新增工具却未增加用例、移除工具后遗留用例、只更新单一入口、输入 Schema 漂移、未实际实现的操作、返回错误结果或破坏只读权限，都会导致检查失败。Python 门禁回归测试证明缺失、重复、失效用例及无断言用例确实被拒绝。

这不等同于自动证明所有产品语义，也无法自动判断某个只写在桌面里的功能是否应该暴露为操作。界面布局等不适用项需要在 PR 中解释，由审阅者确认。

## 本地执行

```bash
source tools/env.sh
dotnet build tests/Meili.Automation.Host/Meili.Automation.Host.csproj -c Release
python3 -m unittest discover -s tests/automation -p test_capability_guard.py -v
python3 tests/automation/check_capability_coverage.py
python3 tests/automation/cli_mcp_smoke.py --dll src/Meili.Cli/bin/Release/net10.0/easysellput.dll
```

`bash build/test-headless.sh` 已集成以上检查，并执行六个跨平台测试项目。Windows 可先加载 tools/env.ps1，再用 python 代替 python3。Linux 无窗口渲染需要系统字体；`build/ci-fonts.conf` 是 CI 的 Fontconfig 配置。

## 强制合并条件

提交并推送这些文件后，GitHub Actions 才会实际运行。管理员需在 GitHub **Settings → Rules → Rulesets**（或 Branch protection）对 main 开启“Require status checks to pass”，将 **CLI and MCP required** 设置为必需检查。

仅添加 workflow 不会自动修改仓库分支保护；未设为必需检查时，GitHub 仍可能允许合并失败的 PR。本次不修改远端规则，也不推送本地改动。

## macOS runner 调度与架构

初次运行的 macos-15（ARM64）任务因 GitHub 官方 runner 容量不足，未被 runner 接收而被取消；保留该失败记录，不把它当作代码测试通过。默认改用官方 macos-15-intel，仍执行完整 macOS 原生构建、协议及发行程序检查，没有移除测试或放宽 required 门禁。

手动 workflow_dispatch 可通过 macos_runner 选择 macos-15，在 ARM64 容量恢复后独立验证。Intel runner 通过只证明 macOS x64 的原生流程，不等价于 Apple Silicon 原生运行通过。官方标签依据：https://github.com/actions/runner-images#available-images 。
